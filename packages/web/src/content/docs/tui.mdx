OpenCode provides an interactive terminal interface or TUI for working on your projects with an LLM.

Running OpenCode starts the TUI for the current directory.

```bash
opencode
```

Or you can start it for a specific working directory.

```bash
opencode /path/to/project
```

Once you're in the TUI, you can prompt it with a message.

```text
Give me a quick summary of the codebase.
```

### When a prompt fails to send

The prompt clears as soon as you press Enter, but the TUI keeps what you sent until the server has stored it. If the send takes longer than a moment, the status line below the prompt shows **Sending prompt**.

- **The server rejects it.** The TUI shows **Failed to send prompt** and puts your text and attachments back in the prompt, ready to send again. If you have typed something new in the meantime, the rejected prompt goes above it, separated by a `--` line, and the cursor stays where it was in your new text. If your new text already contains the rejected prompt, nothing changes. The status line keeps a note of what happened until you send another prompt.
- **The outcome is unknown.** When the connection drops or a proxy answers with a gateway error, the server may still have received the prompt. The TUI checks by looking the message up, and keeps checking every 5 seconds for two minutes. Until it is found, the status line shows **Prompt may not have been received**. Click it, or run **Resend unconfirmed prompt** from the command palette, to send it again. To edit it before sending, run **Restore unconfirmed prompt** instead.

A resend looks the message up first and reuses the same message ID, so a prompt that did arrive is never stored or answered twice. The server treats a prompt whose message ID it already has as the same prompt: it waits for the first send if that is still in progress, and otherwise returns the reply it already has instead of starting another turn, even when that turn failed or was interrupted.

### Message actions

Click a prompt in the conversation to act on it:

| Action | What it does |
|---|---|
| **Revert messages** | Removes this prompt and everything after it, and puts the prompt back in the prompt box. Files stay as they are. |
| **Revert messages and files** | The same, and also reverts the file changes those messages made. |
| **Copy** | Copies the prompt's text. |
| **Expand provenance** / **Collapse provenance** | Opens or closes the prompt's [delivery provenance](#delivery-provenance). Listed only for a prompt that has one. |
| **Copy provenance** | Copies the prompt's full delivery text. Listed only for a prompt that has [delivery provenance](#delivery-provenance). |
| **Fork** | Starts a new session from the conversation before this prompt. |

The two Revert actions are listed with [`revert.files`](#options)'s choice first. The conversation shows the revert at once; if the server refuses it, for example because a turn is running, it comes back and a notice says why.

A prompt sent while a turn is running waits, marked **QUEUED**, until the turn reaches it. Click it and choose **Unqueue** to take it back: it leaves the queue and its text and attachments return to the prompt box, above anything typed there since. The running turn keeps going. If the turn has already picked the prompt up, nothing changes and a notice says so.

### Delivery provenance

A prompt that another session or tool delivered, such as a Vibeterm `vibeterm_prompt_session` message, starts with a short `[vibeterm_metadata]` block naming the sender. The model reads only that short block. The full record of the delivery can travel with the prompt as metadata on its text part, `metadata.vibeterm = { schema: 1, provenance: { block, entries, displayText?, modelText } }`, and that metadata is never sent to the model. `modelText` is the exact text the record was written for. A TUI plugin sends the record with `api.prompt.deliver({ sessionID, text, metadata })` when `api.prompt.deliveryMetadata` is `true`; a prompt sent over the server API carries it as its text part's `metadata`.

A prompt with a full record shows one more row below its text: `▸ Delivery provenance · N fields · Click to expand`. Click it, choose **Expand provenance** in the prompt's [message actions](#message-actions), or press `ctrl+x p` to open every one in the session at once. Opened, it shows:

- The full text the sender wrote: `displayText` when the record has it, otherwise the prompt with its short block swapped for the full one, every field and `*_local` time included.
- **Fields**: every field of the record, nested fields and lists in the block's own `key: value` shape.

**Copy provenance** copies that full text. A prompt without a record, with a record the TUI cannot read (another `schema`, or fields that disagree with the block), or whose text is no longer exactly the record's `modelText` looks exactly as before, so an edited prompt never shows a stale record.

## File references

You can reference files in your messages using `@`. This does a fuzzy file search in the current working directory.

:::tip
You can also use `@` to reference files in your messages.
:::

```text "@packages/functions/src/api/index.ts"
How is auth handled in @packages/functions/src/api/index.ts?
```

The content of the file is added to the conversation automatically.

Configured [references](/docs/references) also appear in `@` autocomplete. Type `@alias` to add the reference root as context, or type `@alias/` to autocomplete files inside that reference.

```text "@docs/README.md"
Compare our setup with @docs/README.md
```

## Bash commands

Start a message with `!` to run a shell command.

```bash frame="none"
!ls -la
```

The output of the command is added to the conversation as a tool result.

## Clickable elements

These parts of the screen act when you click them. Where a keybind or slash command does the same, the click runs it:

| Element | Where | Action |
| --- | --- | --- |
| A pasted-text placeholder, such as `[Pasted ~12 lines]` | In the prompt | Opens the pasted text to read and edit. See [Paste summary](#paste-summary) |
| Agent name | Below the prompt | Opens the agent picker (`/agents`) |
| Model and provider | Below the prompt | Opens the model picker (`/models`) |
| Variant | Below the prompt, when one is selected | Opens the variant picker (`/variants`) |
| `tab agents` | Below the prompt | Switches to the next agent, like `tab` |
| `ctrl+p commands` | Below the prompt | Opens the command palette |
| `esc interrupt` | Below the prompt, while the agent works | Like pressing `esc`: the first click asks for a second, and a second click within 5 seconds interrupts the agent |
| Token, context and cost usage | Below the prompt, and the Context section of the session sidebar | Opens the status dialog (`/status`) |
| Directory | Below the prompt, the session sidebar footer, the home screen footer | Copies the directory's path |
| Model in a message footer | After `▣` and the agent below an answer | Opens the model picker with the model that turn ran on highlighted |
| `Delivery provenance` row | Below a prompt that carries a full delivery record | Opens or closes the record. See [Delivery provenance](#delivery-provenance) |
| Session title | Top of the session sidebar | Renames the session (`/rename`) |
| Session ID | Below the session title in the sidebar | Copies the ID |
| Message ID (`msg_...`) | Message footers, when [`footer.message_id`](#footer) shows them | Copies the ID |
| An ID in the transcript | Text the agent or a tool wrote: a session or message ID, any other prefixed ID such as `prt_...`, or a tool call ID after a `callID:` label | Copies the ID, unless a plugin handles it (see below) |
| An MCP server | MCP section of the session sidebar | Connects or disconnects that server, as `/mcps` does, without opening the dialog. The dot shows `⋯` until the server answers. |
| A modified file | Modified Files section of the session sidebar | Opens the diff viewer (`/diff`) at that file |
| A todo | Todo section of the session sidebar | Copies the todo and adds it to the end of the prompt |
| MCP count and `/status` | Home screen footer | Opens the status dialog (`/status`) |
| Connect provider | "Getting started" box in the session sidebar | Opens the provider list (`/connect`) |

A click counts only when the mouse is pressed and released on the same cell. Dragging across any of these selects and copies its text instead, as it does elsewhere, and nothing happens on hover. A click on an ID inside a message, tool call or footer acts on the ID, not on the message or tool around it.

A TUI plugin can take clicks on IDs in the transcript with `api.click.on(handler)`, for example to open the session the ID names. The handler gets `{ target: { kind: "session" | "message" | "id" | "commit", value, before }, context: { sessionID } }` and returns `true` to take the click; otherwise the ID is copied. `id` is any other prefixed ID whose body starts with a hex timestamp, as every ID opencode mints does, or a tool call ID after a `callID:` label; `before` is the text left of it on its row. `commit` is a run of 7 to 40 lowercase hex holding both a digit and a letter, which may be a git commit hash; whether it names one is the handler's question, and one no handler takes is left alone rather than copied. IDs in message footers and the sidebar always copy.

## Commands

When using the OpenCode TUI, you can type `/` followed by a command name to quickly execute actions. For example:

```bash frame="none"
/help
```

Most commands also have keyboard shortcuts using `ctrl+x` as the default leader key. [Learn more](/docs/keybinds).

### redo

Redo a previously undone message. Only available after using `/undo`.

:::

be a Git repository**.

```bash frame="none"

```

**Keybind:** `ctrl+x r`


**Keybind:** `ctrl+x t`

---

### thinking

Toggle the visibility of thinking/reasoning blocks in the conversation. When enabled, you can see the model's reasoning process for models that support extended thinking.

:::note
This command only controls whether thinking blocks are **displayed** - it does not enable or disable the model's reasoning capabilities. To toggle actual reasoning capabilities, use `ctrl+t` to cycle through model variants.
:::

```bash frame="none"
/thinking
```

---

### undo

Undo last message in the conversation. Removes the most recent user message and all subsequent responses. Files stay as they are unless [`revert.files`](#options) is `true`, which also reverts the file changes those messages made.

:::tip
`/undo-messages` always keeps the files and `/undo-files` always reverts them, whatever `revert.files` says.
:::

Internally, this uses Git to manage the file changes. So your project **needs to
be a Git repository**.

```bash frame="none"
/undo
```

**Keybind:** `ctrl+x u`

---

### undo-files

Undo last message and the file changes it made.

```bash frame="none"
/undo-files
```

---

### undo-messages

Undo last message and keep every file as it is. Nothing is snapshotted, so a later `/redo` restores the messages only and never touches a file.

```bash frame="none"
/undo-messages
```

---

### unshare

Unshare current session. [Learn more](/docs/share#un-sharing).

```bash frame="none"
/unshare
```

---

### update

Check for a new version of OpenCode and install it. If a newer OpenCode 1 release is available, the dialog installs it. If OpenCode 1 is up to date, it offers to upgrade you to OpenCode 2.0 instead. OpenCode never installs updates on its own, so a notice on the home screen tells you when one is available. Choosing **Skip** on an OpenCode 1 update hides the notice until a newer version is released, and choosing **Dismiss** on the OpenCode 2.0 offer hides it for a week.

```bash frame="none"
/update
```

## Editor setup

Both the `/editor` and `/export` commands use the editor specified in your `EDITOR` environment variable.

<Tabs>
  <TabItem label="Linux/macOS">
    ```bash
    # Example for nano or vim
    export EDITOR=nano
    export EDITOR=vim

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    export EDITOR="code --wait"
    ```

    To make it permanent, add this to your shell profile;
    `~/.bashrc`, `~/.zshrc`, etc.

  </TabItem>

  <TabItem label="Windows (CMD)">
    ```bash
    set EDITOR=notepad

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    set EDITOR=code --wait
    ```

    To make it permanent, use **System Properties** > **Environment
    Variables**.

  </TabItem>

  <TabItem label="Windows (PowerShell)">
    ```powershell
    $env:EDITOR = "notepad"

    # For GUI editors, VS Code, Cursor, VSCodium, Windsurf, Zed, etc.
    # include --wait
    $env:EDITOR = "code --wait"
    ```

    To make it permanent, add this to your PowerShell profile.

  </TabItem>
</Tabs>

Popular editor options include:

- `code` - Visual Studio Code
- `cursor` - Cursor
- `windsurf` - Windsurf
- `nvim` - Neovim editor
- `vim` - Vim editor
- `nano` - Nano editor
- `notepad` - Windows Notepad
- `subl` - Sublime Text

:::note
Some editors like VS Code need to be started with the `--wait` flag.
:::

Some editors need command-line arguments to run in blocking mode. The `--wait` flag makes the editor process block until closed.

## Configure

You can customize TUI behavior through `tui.json` (or `tui.jsonc`).

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "theme": "opencode",
  "leader_timeout": 2000,
  "keybinds": {
    "leader": "ctrl+x",
    "command_list": "ctrl+p"
  },
  "scroll_speed": 3,
  "scroll_acceleration": {
    "enabled": false
  },
  "diff_style": "auto",
  "model_label": "name",
  "footer": {
    "time": "user,tool",
    "duration": "important"
  },
  "cursor": {
    "style": "block",
    "blinking": true
  },
  "mouse": true,
  "attention": {
    "enabled": true,
    "notifications": true,
    "sound": true,
    "volume": 0.4,
    "sound_pack": "opencode.default",
    "sounds": {
      "error": "./sounds/error.mp3"
    }
  }
}
```

This is separate from `opencode.json`, which configures server/runtime behavior.

`keybinds` is merged with built-in defaults, so you only need to configure the shortcuts you want to change.

#### Home and End

The `home` and `end` keys follow the editor-standard scheme used by VS Code and most text editors:

| Keys | Action |
|---|---|
| `home` / `end` | Start / end of the line in the prompt (also `ctrl+a` / `ctrl+e`) |
| `shift+home` / `shift+end` | Select to the start / end of the line |
| `ctrl+home` / `ctrl+end` | Start / end of the whole prompt |
| `ctrl+shift+home` / `ctrl+shift+end` | Select to the start / end of the whole prompt |
| `ctrl+alt+home` / `ctrl+alt+end` | Top / bottom of the conversation (also `ctrl+g` / `ctrl+alt+g`) |

No key is shared between the prompt and conversation scrolling, so each one does the same thing whether or not the prompt has text in it. While the which-key panel is open, `ctrl+alt+home` / `ctrl+alt+end` scroll the panel instead.

### Options

- `theme` - Sets your UI theme. [Learn more](/docs/themes).
- `keybinds` - Customizes keyboard shortcuts. [Learn more](/docs/keybinds).
- `leader_timeout` - Controls how long OpenCode waits after the leader key. Defaults to `2000`.
- `scroll_acceleration.enabled` - Enable macOS-style scroll acceleration for smooth, natural scrolling. When enabled, scroll speed increases with rapid scrolling gestures and stays precise for slower movements. **This setting takes precedence over `scroll_speed` and overrides it when enabled.**
- `scroll_speed` - Controls how fast the TUI scrolls when using scroll commands (minimum: `0.001`, supports decimal values). Defaults to `3`. **Note: This is ignored if `scroll_acceleration.enabled` is set to `true`.**
- `diff_style` - Controls diff rendering. `"auto"` adapts to terminal width, `"stacked"` always shows a single-column layout.
- `busy_indicator` - The animation left of `esc interrupt` while a turn runs, in the TUI and in `opencode run`. `"scanner"` (default) slides a bar left and right; `"spinner"` turns a single cell, like the other busy notices such as **Sending prompt**. The scanner holds still for most of its cycle, so on a lagging host many of its frames look the same. Every spinner frame draws a different glyph, so you can still tell the turn is alive.
- `footer` - Chooses which details message footers and other transcript entries show: agent, model, variant, time, duration, total and message ID. See [Footer](#footer).
- `datetime_format` - How times and dates are written. See [Date and time format](#date-and-time-format).
- `tool_output.collapse` - How much of a tool's output shows before **Click to expand**. See [Tool output](#tool-output).
- `prompt.min_height`, `prompt.max_height`, `prompt.max_width` - How tall the prompt starts, how tall it grows before it scrolls, and how wide the home screen prompt is. See [Prompt size](#prompt-size).
- `home.logo`, `home.tips`, `home.prompt_position`, `home.prompt_min_height`, `home.prompt_max_height` - Whether the home screen shows the logo and a tip, where its prompt sits, and how tall that prompt is. See [Home screen](#home-screen).
- `prompt.paste_summary` - When a paste is replaced by a placeholder such as `[Pasted ~12 lines]`, and what the placeholder says. See [Paste summary](#paste-summary).
- `prompt.paste_mode` - What pasting text does: `"direct"` (default) puts it in the prompt; `"dialog"` opens the paste dialog first. See [Paste dialog](#paste-dialog).
- `prompt.undo_depth` - How many steps of prompt edits undo can take back. Defaults to `500`. See [Undo in the prompt](#undo-in-the-prompt).
- `prompt.history_scope` - Which prompts <kbd>up</kbd> and <kbd>down</kbd> recall in a session: `"global"` (default) or `"session"`. See [Prompt history](#prompt-history).
- `input.line_discard` - What <kbd>ctrl+u</kbd> (`input_delete_to_line_start`) deletes in the prompt and every other text field: `"bash"` (default) deletes from the cursor back to the start of its line, as bash does; `"zsh"` deletes the whole line wherever the cursor is, as zsh does. In a multi-line prompt it is the cursor's line, never the rest of the prompt; on a line that is already empty, or with the cursor at its start under `"bash"`, it joins the line to the one above. <kbd>ctrl+k</kbd> (`input_delete_to_line_end`) and `input_delete_line` are unchanged, and `input_undo` brings the text back.
- `model_label` - How message footers and the prompt name a model: `"name"` (default) shows its display name, such as `Claude Sonnet 4.5`; `"id"` shows `providerID/modelID`, such as `anthropic/claude-sonnet-4-5`.
- `turn_timing`, `footer_variant`, `timestamps` - Older settings that `footer` replaces; they keep working. See [Older footer settings](#older-footer-settings).
- `cursor` - Controls the terminal cursor in TUI input fields. `style` defaults to `"block"`, can be `"underline"`, `"line"`, or `"default"`; `blinking` defaults to `true`. When `style` is `"default"`, the terminal default cursor is restored, so `blinking` has no effect.
- `sidebar.context` - Controls the sidebar Context block. `"expanded"` (default) shows tokens, percent used, and cost on separate lines; `"compact"` fits them on one line, abbreviating as the sidebar narrows. Click the block's arrow or run "Compact sidebar context" from the command palette to switch at runtime. See [Settings with a toggle](#settings-with-a-toggle).
- `usage.context_color` - Colors the context usage in the sidebar Context block (expanded and compact) and in the prompt footer. `"plain"` (default) keeps the muted text color; `"colored"` colors the token count and percent used by `usage.context_thresholds`.
- `usage.context_thresholds` - Percent-used thresholds for `"colored"`. Defaults to `[60, 70, 80, 90]`: up to 60% stays muted, above 60% uses the theme's warning color, above 90% its error color, and the thresholds in between blend from warning to error.
- `usage.cost_thresholds` - Dollar thresholds for the session cost in the sidebar and the prompt footer, colored the same way: above the first uses the warning color, above the last the error color. Unset by default, so cost stays muted. For example, `[5, 20]` shows the cost in the warning color above $5 and in the error color above $20.
- `sidebar.mcp_summary` - Controls the summary next to the sidebar MCP heading. `"default"` shows `(N active, M errors)` while the list is collapsed; `"collapsed"` shows a colored status dot and count per status (connected, failed, needs client ID, needs auth, disabled) while collapsed; `"always"` shows those counts whether the list is collapsed or expanded; `"never"` shows no summary.
- `sidebar.mcp_list` - Controls the MCP server rows in the session sidebar. `"descriptive"` (default) shows the status dot, the server name and its status text (`Connected`, `Disabled`, the failure reason, and so on); `"compact"` shows only the status dot and the server name, leaving the dot color to carry the status. `/status` still lists every server with its full status.
- `sidebar.todo_summary` - Shows todo counts after the sidebar Todo heading: `"never"` (default), `"collapsed"` (only while the list is collapsed; lists of two or fewer items never collapse), or `"always"`. `sidebar.todo_summary_style` picks the format: `"progress"` (default) is completed+in progress/total, e.g. `10+1/12`; `"icons"` is a count per status, e.g. `✓10 •1 ○1`.
- `sidebar.todo_completed` - What the sidebar Todo section does once every item is completed: `"hide"` (default) removes it, `"collapsed"` keeps the heading and collapses the list (lists of two or fewer items never collapse), `"show"` keeps the list open.
- `revert.files` - Whether `/undo`, its keybind and the first Revert action in [message actions](#message-actions) also revert the file changes the reverted messages made (default: `false`). The other choice is always one row down in message actions, or `/undo-messages` and `/undo-files`, which you can bind with `messages_undo_keep_files` and `messages_undo_with_files`.
- `mouse` - Enable or disable mouse capture in the TUI (default: `true`). When disabled, the terminal's native mouse selection/scrolling behavior is preserved.
- `keep_scroll_on_submit` - Keep the session scroll position when a prompt is submitted instead of jumping to the bottom (default: `false`). Toggle it at runtime with `/keep-scroll`. See [Settings with a toggle](#settings-with-a-toggle).
- `sidebar.pin_title` - Keep the session title at the top of the sidebar while the rest of the sidebar scrolls (default: `false`). The `/pin-title` command toggles it. See [Settings with a toggle](#settings-with-a-toggle).
- `sidebar.session_id` - Show the session ID on the line below the session title in the sidebar, in the muted text color (default: shown only in development builds). The `/session-id` command toggles it. See [Settings with a toggle](#settings-with-a-toggle).
- `transcript.max_messages` - How many of a session's most recent messages the TUI keeps loaded (default: `100`). Older messages are hidden behind a divider: a rule with the hidden count and `load all`, `load 50 above` and `load 100 above` above it, and `load 50 below` and `load 100 below` under it. "Above" fills the gap from its older edge, "below" from its newer edge; a page as big as the gap is left out, since `load all` does the same. Loading every message costs about 10 ms and 0.5 MB of memory per message, so `load all` reads `load all (slow)` from 300 hidden messages and `load all (slow / memory heavy)` from 500. The same actions are in the command palette, `/load-hidden` loads all of them, and the `messages_hidden_*` keybinds are unbound by default.
- `transcript.keep_first_prompt` - Keep the session's first prompt at the top, above the divider, when older messages are hidden (default: `true`).
- `transcript.show` - Which kinds of entries the session transcript shows, the same choices as the [transcript filter](#transcript-filter) dialog. See [Settings with a toggle](#settings-with-a-toggle).
- `attention` - Configures TUI desktop notifications and sounds. Disabled by default.
- `syntax` - Controls syntax highlighting in tool calls. [Learn more](#syntax-highlighting).
- `sidebar.order` - Session sidebar sections in display order, for example `["todo", "context"]`. Built-in sections are `context`, `mcp`, `lsp`, `todo`, and `files`; plugin sections use their plugin id. Sections you do not list follow in their default order. The session title always stays first.
- `sidebar.hidden` - Session sidebar sections to hide, using the same names as `sidebar.order`.

You can also drag a sidebar section by its header to a new place with the mouse. **Reset sidebar order** in the command palette drops a dragged order. See [Settings with a toggle](#settings-with-a-toggle).

- `startup` - Controls what happens while OpenCode starts. See [Startup](#startup).

### Settings with a toggle

Several settings can also be flipped while OpenCode runs, from the command palette, a slash command, a click or a drag. tui.json and the toggle never fight over the same setting:

- **Set in tui.json**, the setting decides on every start. The toggle lasts until OpenCode exits, and a toast says so. Toggling back to the tui.json value clears it.
- **Left unset**, the toggle is remembered across restarts, in `kv.json` in OpenCode's state directory.

| Setting | Toggle |
| --- | --- |
| `home.tips` | **Show tips** / **Hide tips** |
| `sidebar.context` | Click the Context arrow, or **Compact sidebar context** / **Expand sidebar context** |
| `sidebar.pin_title` | `/pin-title` |
| `sidebar.session_id` | `/session-id` |
| `sidebar.order` | Drag a section header; **Reset sidebar order** |
| `keep_scroll_on_submit` | `/keep-scroll` |
| `footer.time`, `footer.duration`, `timestamps`, `turn_timing` | `/timestamps`, `/turn-times`, `/turn-durations` |
| `tool_output.collapse.generic` | **Show generic tool output** / **Hide generic tool output** |
| `transcript.show` | `/filter`, one kind at a time; **Show tool calls** / **Hide tool calls** for `transcript.show.tools` |

A toggle remembered on one run never overrides a value you set in tui.json later.

Use `OPENCODE_TUI_CONFIG` to load a custom TUI config path.

### Transcript filter

`/filter`, `ctrl+x f` or **Filter transcript** in the command palette lists every kind of entry the session transcript draws, most important first, with how many of each are loaded. A ticked kind shows. Up and down move, space or a click toggles, the wheel scrolls, and enter or esc closes. The transcript changes as you toggle, behind the dialog.

| Kind | What it is | `transcript.show` key |
| --- | --- | --- |
| Prompts | What you sent | `prompts` |
| Final answers | Each turn's final response | `answers` |
| Questions | Questions the agent asked, with your answers | `questions` |
| Errors | A failed turn's error box, and every failed tool call, whatever its own kind says | `errors` |
| Notices | Messages left for you that the model never sees, such as Vibeterm's `user_message` | `notices` |
| Todos | Todo list updates | `todos` |
| Subagents | Subagent tasks and the hint to view them | `subagents` |
| Progress notes | Text the agent writes between tool calls, before its final response | `notes` |
| File actions | The `read`, `edit`, `write`, `apply_patch`, `grep`, `glob` and `list` tools, and bash commands that only read or search files: `cat`, `head`, `tail`, `sed` without `-i`, `grep`, `rg` and `git show <ref>:<path>`, with no redirect | `file_actions` |
| Tool calls | Every other tool call, plugin and MCP tools included | `tools` |
| Thinking | Thinking blocks; `/thinking` still expands or collapses them | `thinking` |
| Compaction markers | The divider where the session was compacted | `compaction` |
| Turn footers | The line under each turn: agent, model and what [`footer`](#footer) selects | `footers` |

Unticking **Tool calls** opens a second level below it: this session's ten most used tools and **Other tools**, all unticked, so ticking some shows only those. **File actions** works the same way over **Edits, writes and patches**, **Reads** and **Searches**. The counts and the ten tools are worked out once, when the dialog opens.

A hidden entry leaves no gap. A tool call still running, a thinking block still thinking and a response still being written show whatever the filter says, so a working turn is never blank. When everything loaded is hidden, the transcript says so in one line, which opens the dialog when clicked.

In tui.json each key takes `true` or `false`; `tools` also takes a list of tool names, and `file_actions` a list of `"edits"`, `"reads"` and `"searches"`, to show only those:

```json title="tui.json"
{
  "transcript": {
    "show": {
      "thinking": false,
      "tools": ["bash", "webfetch"],
      "file_actions": ["edits"]
    }
  }
}
```

A key set there decides on every start and the dialog's toggle for that kind lasts until OpenCode exits; unset kinds are remembered in `kv.json`. **Show tool calls** / **Hide tool calls** is the same toggle as the **Tool calls** row, and the export dialog starts from the **Thinking**, **Tool calls** and **Turn footers** rows.

### Footer

`footer` chooses which details the session transcript shows, one key per detail. Every key takes the same value:

- `"all"` or `true` - everywhere the detail applies.
- `"none"` or `false` - nowhere.
- `"important"` - only on landmarks, the entries <kbd>ctrl+shift+up</kbd> and <kbd>ctrl+shift+down</kbd> stop on: your prompts, the final response of each turn, and question, todo and subagent tool calls. An assistant footer counts when its message holds one of those.
- A list of entry types, as a comma-separated string such as `"user,tool"` or an array such as `["user", "tool"]`. It may include `"important"`: `"user,important"`.

| Key          | Shows                                                                                    | Applies to                                                                  | Default            |
| ------------ | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------ |
| `agent`      | The agent that ran the turn                                                              | `assistant`                                                                 | `"all"`            |
| `model`      | The model the turn ran on, named per `model_label`                                       | `assistant`                                                                 | `"all"`            |
| `variant`    | The variant the turn ran with, such as its reasoning effort (`high`), after the model    | `assistant`                                                                 | `"none"`           |
| `time`       | When the entry happened                                                                  | `user`, `assistant`, `text`, `reasoning`, `tool`, `error`, `compaction`     | see below          |
| `duration`   | How long the entry took                                                                  | `assistant`, `reasoning`, `tool`                                            | `"reasoning"`      |
| `total`      | Time from your prompt to the end of the turn                                             | `assistant`, final message of a turn only                                   | `"all"`            |
| `message_id` | The message ID (`msg_...`), which you can click or select to copy                        | `user`, `assistant`, `tool`                                                 | `"none"`           |

| Type         | Where                                                         |
| ------------ | ------------------------------------------------------------- |
| `user`       | Below the prompt                                              |
| `assistant`  | In the turn footer                                            |
| `text`       | Below an assistant text block, when it finished               |
| `reasoning`  | In the thinking block header                                  |
| `tool`       | Every tool call, plugin and MCP tools included                |
| `error`      | In the error box of a failed turn                             |
| `compaction` | In the compaction divider, when compaction started            |

A type a key does not apply to has no effect, so `"all"` and `"important"` select only the entries listed under _Applies to_. A turn's last message always has a footer; `time`, `duration` and `message_id` also give its earlier messages, such as tool-call steps, a footer once they finish. A time from today shows the time of day; an older one shows the date, then the time, written per [`datetime_format`](#date-and-time-format). On a tool call, `time`, `duration` and `message_id` follow the call on one line, `· 9:16 PM · 1.5s · msg_...`; a call drawn as a block, or one whose arguments span lines, puts them on its own last line so a long command or prompt cannot push them out of sight. A block that ends in a hint keeps them on that line: `Click to expand · 9:16 PM · 1.5s`.

Each message ID appears once. A tool call belongs to its assistant message, so the tool call shows the message's ID only when the message's own footer does not: with `"message_id": "tool"`, or when `"important"` leaves that step's footer out. With `"all"`, the ID is in the assistant footer and the tool calls show only their time and duration.

While a tool call runs, its footer shows when it started and a stopwatch that ticks every second in whole seconds: `16:25:29 · 37s`, `16:25:29 · 2m 5s`. Once it finishes, the footer shows when it finished and how long it ran, with tenths of a second up to 11 minutes: `4.8s`, `2m 5.3s`, then `11m 0s`. One clock drives every running call, and it stops when none is running.

A prompt's footer sits one blank line below the prompt's text, unless the text already ends with a blank line or file chips sit between them.

```json title="tui.json"
{
  "footer": {
    "variant": "all",
    "time": "important",
    "duration": "assistant,tool",
    "message_id": ["user", "assistant"]
  }
}
```

The `/timestamps`, `/turn-times` and `/turn-durations` commands flip prompt times, turn times and turn durations, as described in [Settings with a toggle](#settings-with-a-toggle).

### Date and time format

`datetime_format` sets how times and dates are written in message footers, entry timestamps, the compaction divider and the timeline and stash dialogs. It has a `date` and a `time` pattern. Entries from today show only the time; older ones show the date, then the time. A part left unset keeps your locale's format (`2:20 PM`, `10/7/2026`), so with neither set nothing changes.

```json title="tui.json"
{
  "datetime_format": {
    "date": "YYYY-MM-DD",
    "time": "HH:mm:ss"
  }
}
```

This shows `14:20:07` for today and `2026-10-07 14:20:07` for an older entry. At midnight, entries already on screen switch to the date-and-time form on their own; a closed laptop or a clock change is caught within the hour.

| Part   | Token  | Writes                    |
| ------ | ------ | ------------------------- |
| `date` | `YYYY` | Year, `2026`              |
| `date` | `YY`   | Two-digit year, `26`      |
| `date` | `MM`   | Month, `01`-`12`          |
| `date` | `M`    | Month, `1`-`12`           |
| `date` | `DD`   | Day, `01`-`31`            |
| `date` | `D`    | Day, `1`-`31`             |
| `time` | `HH`   | Hour, `00`-`23`           |
| `time` | `H`    | Hour, `0`-`23`            |
| `time` | `hh`   | Hour, `01`-`12`           |
| `time` | `h`    | Hour, `1`-`12`            |
| `time` | `mm`   | Minute, `00`-`59`         |
| `time` | `m`    | Minute, `0`-`59`          |
| `time` | `ss`   | Second, `00`-`59`         |
| `time` | `s`    | Second, `0`-`59`          |
| `time` | `A`    | `AM` or `PM`              |
| `time` | `a`    | `am` or `pm`              |

Uppercase `MM` is always the month and lowercase `mm` the minute. Each part accepts only its own tokens, so a time written as `HH:MM:SS` is rejected rather than shown with the month in place of the minute. Any other letter must be put in brackets: `h[h]mm` writes `2h20`. Digits, spaces and punctuation are written as they are.

### Tool output

`tool_output.collapse` sets how many lines of a tool block's output show before **Click to expand**. Clicking the block expands it to the full output, and clicking again collapses it.

```json title="tui.json"
{
  "tool_output": {
    "collapse": {
      "bash": 0,
      "generic": 10,
      "edit": 20,
      "vibeterm_prompt_session": 0
    }
  }
}
```

| Key           | Covers                                                          | Default   |
| ------------- | --------------------------------------------------------------- | --------- |
| `bash`        | Shell commands and their output                                 | `10`      |
| `generic`     | Plugin, MCP and other tools without a view of their own         | `3`       |
| `write`       | The content of a written file                                   | `"never"` |
| `edit`        | The diff of an edited file                                      | `"never"` |
| `apply_patch` | The diff of each patched file                                   | `"never"` |
| a tool name   | That tool only, overriding its group: `"vibeterm_prompt_session"` | its group |

Each value is a number of lines or `"never"`:

- A number shows that many lines, then `…` and the hint. A long line counts as more than one: the preview is capped at that many lines' worth of characters.
- `0` hides the output until clicked, even with `tail` and `head` (below) set. The block is just its title or command, a blank line, and the hint, with the [footer](#footer) on the hint line: `Click to expand · 16:13:02 · 1.5s`.
- `"never"` always shows all of it, with no hint.

`write`, `edit` and `apply_patch` count rendered rows of the file or diff, so a side-by-side diff collapses to that many rows. A deleted file in a patch is a single line and never collapses. Generic tools show their output only while **Show generic tool output** is on, unless `generic` or the tool's own name is set here: then the output shows, collapsed to that limit, on every start. With `generic` set, **Hide generic tool output** lasts until OpenCode exits. See [Settings with a toggle](#settings-with-a-toggle).

`tool_output.tail` shows the **last** lines of collapsed output instead of the first, under `(N earlier lines)`, per group (`bash`, `generic`) or tool name. A tool name overrides its group. It is off by default.

```json title="tui.json"
{
  "tool_output": {
    "collapse": { "bash": 10 },
    "tail": { "bash": true, "browser": false }
  }
}
```

With `bash` at 10, a 40-line output collapses to `(31 earlier lines)` and lines 32 to 40.

`tool_output.head` keeps the **first** lines as well: with `tail` on, that many first lines stay above a `(N more lines)` marker, and the last lines fill the rest of the `collapse` limit. It is set per group (`bash`, `generic`) or tool name, a tool name overrides its group, and it is `0` by default. To see the first 2 and the last 2 lines of bash output:

```json title="tui.json"
{
  "tool_output": {
    "collapse": { "bash": 5 },
    "tail": { "bash": true },
    "head": { "bash": 2 }
  }
}
```

A 40-line output then collapses to:

```
output line 1
output line 2
(36 more lines)
output line 39
output line 40
```

- The `collapse` limit counts every row, the marker included: `5` is 2 first lines, the marker and 2 last lines.
- `head` is at most the limit minus 2, so at least one last line shows. It does nothing while `tail` is off.
- `collapse` at `0` keeps the output hidden until clicked whatever `tail` and `head` say. For a head and a tail, set the limit to `head` + 1 + the number of last lines.

### Tool input

`tool_input.collapse` sets how many rendered rows of a tool call's input show before **Click to expand**. It takes the same values as `tool_output.collapse`, per group or tool name:

```json title="tui.json"
{
  "tool_input": {
    "collapse": { "bash": 5 }
  }
}
```

| Key         | Covers                                            | Default                      |
| ----------- | ------------------------------------------------- | ---------------------------- |
| `bash`      | The shell command, heredocs included              | `"never"`                    |
| `generic`   | The input block of plugin, MCP and other tools    | one row per value, see below |
| a tool name | That tool only, overriding its group: `"browser"` | its group                    |

The command keeps its wrapping and colors and is cut after that many rows; `0` hides it until clicked. The command and its output keep separate limits: `tool_output.collapse` still decides the output's lines. One click expands both, and the hint and [footer](#footer) are the same as for output.

For `generic` or a plugin or MCP tool's name, the input shows as a block, one key per row, even with `syntax.tool_input` off or when it would fit on the title line. While collapsed every value takes exactly one row, cut with `…` at the end, and at most that many rows show; expanded, every value shows whole, a multi-line string on its own lines. A `browser` call with `action`, `name`, `timeout` and a long `code` script, at `"browser": 4`:

```
# browser

action: run
name: main
timeout: 30
code: const rows = [...document.querySelectorAll('table.identifiers tr')]…
```

Unset, plugin and MCP input follows `syntax.tool_input`: one row per value with no row limit, and whole when `tool_output.collapse` is `"never"` for the tool.

### Syntax highlighting

Tool calls are colored by language, and your own messages can be colored as markdown. Each part can be turned on or off under `syntax`:

```json title="tui.json"
{
  "syntax": {
    "bash": true,
    "heredoc": true,
    "files": true,
    "tool_input": false,
    "file_output": false,
    "user_messages": false
  }
}
```

- `bash` - Color the bash tool's command as shell code. Defaults to `true`.
- `heredoc` - Color each heredoc in a bash command in the language of the command that reads it. Defaults to `true`.
- `files` - Detect the language of written, edited and patched files beyond their extension, so these are colored too: SQL, Dockerfiles (`Dockerfile`, `Containerfile`, `*.dockerfile`), ini-style config and systemd units (`.ini`, `.cfg`, `.conf`, `.service`, `.timer` and the other unit types), dotenv files, shell scripts, ERB, HAML, file names such as `Makefile`, `Gemfile` and `PKGBUILD`, and a `#!` line on a file with no known extension. Defaults to `true`. When `false`, only the file extension decides.
- `tool_input` - Show a plugin or MCP tool's input as a block, one key per line. Defaults to `false`, which shows only the input's text, number and boolean values, as `[key=value, ...]` on the tool's line. With `true`, input that is all such values and fits in 80 characters stays on that line; anything longer, multi-line or nested becomes a block: keys and values in different colors, values colored by type, text unquoted with its newlines, tabs and quotes shown as themselves, nested objects indented beneath their key, and lists laid out as YAML writes them, `- ` items at their key's indent. Until you click the block, every value takes one row, cut with `…` where it no longer fits; clicking shows it whole. With `tool_output.collapse` set to `"never"` for the tool, values always show whole.
- `tool_output` - Color plugin and MCP tool output, by tool name. Keys are tool names or globs (`*` matches any run of characters, `?` one); values are a language id such as `json`, `yaml` or `markdown`, `auto`, `json-as-yaml`, or `none`. An exact name wins over any glob, and the glob with the most literal characters wins over the others. `auto` colors output that is a JSON object or array and leaves anything else plain. `json-as-yaml` recognizes JSON the same way and draws it as YAML rows, in the same layout and colors as a tool's input block; other output stays plain text. See [JSON output as YAML](#json-output-as-yaml). Output over 100,000 characters stays plain. Unset by default, which leaves all output plain. Colored output wraps exactly as the plain text does.
- `file_output` - Color tool output that shows the contents of files in each file's language. Defaults to `false`. See [File contents in tool output](#file-contents-in-tool-output).
- `user_messages` - Color the markdown in the messages you submitted: headings of every level, numbered and bulleted lists, `` `inline code` ``, fenced code blocks in their language, bold, italics, links, `>` quotes and tables. Defaults to `false`. Only colors change: every character shows as you typed it, markers such as `#` and backticks are dimmed rather than hidden, and the message wraps exactly as it does plain. Markdown that people usually write by accident stays plain: a line followed by `---` or `===` is not a heading, four leading spaces are not a code block, a quote covers only the lines that start with `>`, and `*` inside a word, as in `2*3*4`, is not emphasis. Messages over 100,000 characters stay plain.
- `blocks` - Draw blocks in your submitted messages with a formatter instead of as markdown. Each entry has an `open` and a `close` line and a `format`. A block runs from a line that is exactly `open` to the next line that is exactly `close`, surrounding spaces aside; an `open` line with no `close` after it is ordinary text. In `open`, `*` matches a run of non-space characters, and each `*` in `close` stands for what it matched, so one rule covers a family of blocks that each close by name. `format` is `yaml`, which colors `key: value` lines the way a tool input block is colored (keys, values by type, `#` comments and the `open` and `close` lines muted), or any other language id, such as `json` or `sql`, colored by that grammar. Blocks are drawn whether or not `user_messages` is on, and like it they change only colors. Unset by default. A TUI plugin adds blocks with `api.blocks.register({ open, close, format })`; the ones in `tui.json` are tried first.

With `tool_output`, for example:

```json title="tui.json"
{
  "syntax": {
    "tool_output": {
      "browser": "json",
      "todo_*": "none",
      "*": "auto"
    }
  }
}
```

#### File contents in tool output

With `file_output` on, output that shows code from files is colored in each file's language, and a path or line number a line starts with is muted:

| Output                                                                                                                                                                                | Language                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| A bash command reading files: `cat`, `head`, `tail`, `sed -n`, `nl`, `awk`, `bat`, `git show <ref>:<path>`, chained with `;`, `&&` or a pipe through filters such as `head` or `grep` | The files', when they all have one language |
| `grep -n`, `rg` and other `path:12:code`, `path-12-code` and `path:code` lines                                                                                                        | Each line's file                            |
| `rg` with headings: a path line, then `12:code` lines                                                                                                                                 | Each heading's file                         |
| `12:code` or `   12<tab>code` lines from `rg -n` or `cat -n` on files of one language                                                                                                 | The files'                                  |
| A `--type`, `-t` or `--glob` of one language for `rg` and `grep`                                                                                                                      | That language                               |
| Any bash output that is a whole JSON document, or starts like a diff (`git diff`, `git show <commit>`)                                                                                | JSON, diff                                  |
| The read and grep tools                                                                                                                                                               | The file read, each matched file            |
| GitHub code search results (`Repository:`, `Path:` and `--- Snippet` blocks)                                                                                                          | Each snippet's path                         |
| Plugin and MCP output with a fenced code block that names its language, such as context7 docs                                                                                         | Markdown, each block in its own language    |

Output whose language is not clear stays plain: files of different languages read by one command, a command that also runs something else (`ls && cat a.ts`), or a pipe through a command that changes the text (`cat a.json | jq`). A plugin or MCP tool's language set in `tool_output` comes first, and one set to `none` stays plain. Collapsed output, its head, tail and markers included, is colored like the expanded output. Output over 100,000 characters stays plain, and only the first 64 files of a search are colored.

The read and grep tools show no output by default, only their row. With `file_output` on, clicking a finished read or grep row shows the file or the matches it found as a block, colored, and clicking the block folds it back.

#### JSON output as YAML

With `"browser": "json-as-yaml"`, a `browser` call that returns a JSON object shows it the way its input shows: one key per row, nested values indented, strings unquoted. While collapsed every value takes one row, cut with `…` at its end, and `tool_output.collapse_yaml` sets how many rows show before **Click to expand**, per group (`generic`) or tool name; unset, the tool's `tool_output.collapse` applies. Expanded, the whole output shows and a multi-line string is on its own lines. Output that is not JSON stays plain text and keeps `tool_output.collapse`, so text and JSON from the same tool can have different limits:

```json title="tui.json"
{
  "syntax": {
    "tool_output": { "browser": "json-as-yaml" }
  },
  "tool_output": {
    "collapse": { "browser": 3 },
    "collapse_yaml": { "browser": 5 }
  }
}
```

A JSON result then collapses to 5 rows:

```
url: /account/resources/identifiers/list/bundleId/add/bundle-with-a-very-lo…
els:
- - checkbox "App Attest" [checked] [ref=e12]
- - checkbox "Push Notifications" [] [ref=e13]
- - checkbox "Sign in with Apple" [checked] [ref=e14]
```

and a text result to its first 3 lines and `…`. `0` hides the output until clicked, and `"never"` always shows all of it.

With `blocks`, for example, every `[name_*]` ... `[/name_*]` block a tool wraps around its metadata is drawn as YAML:

```json title="tui.json"
{
  "syntax": {
    "blocks": [{ "open": "[vibeterm_*]", "close": "[/vibeterm_*]", "format": "yaml" }]
  }
}
```

A heredoc's language comes from the command that consumes it:

| Command | Language |
| --- | --- |
| `python`, `python3`, `uv` | Python |
| `node` | JavaScript |
| `bun`, `deno`, `tsx` | TypeScript |
| `ruby`, `bundle`, `rails` | Ruby |
| `perl`, `php`, `lua` | Perl, PHP, Lua |
| `sqlite3`, `psql`, `mysql`, `mariadb`, `duckdb`, `clickhouse-client` | SQL |
| `jq`, `curl` | JSON |
| `kubectl`, `yq` | YAML |
| `bash`, `sh`, `zsh`, `ssh` | Shell |
| `git commit`, `gh`, `glab` | Markdown |
| `git apply`, `patch` | Diff |
| `cat > file`, `tee file` | The file's language, by extension |

A command run through `sudo`, `env`, `timeout`, `ssh`, `docker exec` or `kubectl exec` counts as the command it runs, and `cat <<EOF | psql` counts as `psql`. Otherwise a `#!` line at the top of the body decides. A heredoc whose language is still unknown, or has no parser, keeps the shell's string color.

### Prompt size

The prompt starts `prompt.min_height` rows tall, grows with what you type up to `prompt.max_height` rows, and scrolls after that. The home screen prompt uses `home.prompt_min_height` and `home.prompt_max_height` instead where they are set; see [Home screen](#home-screen). It never grows past the screen: on the home screen the logo keeps one row above it, and in a session the transcript gives up its rows. `prompt.max_width` caps the home screen prompt's width; the session prompt always spans the transcript.

```json title="tui.json"
{
  "prompt": {
    "min_height": 3,
    "max_height": "80%",
    "max_width": "60%"
  }
}
```

- `min_height` - Rows the prompt starts at. Defaults to `1`.
- `max_height` - Rows the prompt grows to before it scrolls. Defaults to a third of the terminal height, and at least `6`.
- `max_width` - Columns the home screen prompt is at most. Defaults to `75`. `"auto"` scales it with the terminal: 70% of its width, and at least `75`.

Each also takes a percentage from `"1%"` to `"100%"`. A height percentage is of the rows the prompt can have once everything else on the screen has the room it always keeps: the footer, the logo and the row above it, and the prompt's own padding, agent and status rows. `"100%"` lets the prompt fill all of that. A width percentage is of the home screen's width inside its margins.

### Home screen

```json title="tui.json"
{
  "home": {
    "logo": false,
    "tips": false,
    "prompt_position": "bottom",
    "prompt_min_height": "35%"
  }
}
```

- `logo` - Show the OpenCode logo above the prompt. Defaults to `true`.
- `tips` - Show a tip on the home screen. Defaults to `true`. Set here, it decides on every start, and the **Hide tips** / **Show tips** command lasts until OpenCode exits. Left unset, that command is remembered.
- `prompt_min_height`, `prompt_max_height` - How tall the home screen prompt starts and how tall it grows, the same way `prompt.min_height` and `prompt.max_height` size the session prompt. Each defaults to its `prompt.*` counterpart, so set these to give the home screen a taller prompt than a session, such as `"prompt_min_height": "35%"`.
- `prompt_position` - Where the prompt sits. `"middle"` (default) centers it. `"top"` puts it at the top, so it grows down as you type; `"bottom"` puts it on the footer, so it grows up. The logo stays directly above the prompt. The tip sits below the prompt, except with `"bottom"`, where it moves above the logo so nothing sits between the prompt and the footer.

### Paste summary

A paste of three lines or more, or of more than 150 characters, goes into the prompt as a placeholder such as `[Pasted ~12 lines]`; the pasted text is sent in its place. `prompt.paste_summary` changes when that happens and what the placeholder says:

```json title="tui.json"
{
  "prompt": {
    "paste_summary": {
      "lines": 10,
      "characters": 2000,
      "format": "[Pasted {lines} lines, {bytes} B: {excerpt}]",
      "excerpt": 40
    }
  }
}
```

- `lines` - A paste of at least this many lines is summarized. Defaults to `3`.
- `characters` - A paste longer than this many characters is summarized. Defaults to `150`.
- `format` - The placeholder. Defaults to `"[Pasted ~{lines} lines]"`. `{lines}` is the paste's line count, `{characters}` its length, `{bytes}` its size in UTF-8 bytes, and `{excerpt}` its start, with line breaks and repeated spaces collapsed.
- `excerpt` - How many characters `{excerpt}` shows before it is cut with `…`. Defaults to `30`.

With the example above, a 12-line stack trace that starts with `TypeError: Cannot read properties of undefined` shows as `[Pasted 12 lines, 1834 B: TypeError: Cannot read properties of und…]`. **Disable paste summary** in the command palette turns summarizing off for every paste, and **Enable paste summary** turns it back on.

Click a placeholder to see the text behind it. With `prompt.paste_mode` set to `"dialog"`, it opens the [paste dialog](#paste-dialog) instead. Otherwise it opens in the same editor as the prompt, with the same keys, mouse caret placement and undo. <kbd>enter</kbd> or <kbd>esc</kbd> saves and closes, and the prompt's newline keys (`input_newline`, such as <kbd>shift+enter</kbd>) add a line. The placeholder keeps the edited text, and its label is redone from `format` when the text changed it, such as a new line count. Above the editor, **Keep as block** does the same as <kbd>enter</kbd>, and **Insert inline** replaces the placeholder with the text itself, as if it had been pasted without one. Click a button, or press <kbd>tab</kbd> to move from the editor to Keep as block, Insert inline and back to the editor wherever the caret is (<kbd>shift+tab</kbd> goes the other way), and <kbd>enter</kbd> to press the selected one. <kbd>up</kbd> on the editor's first line also selects the buttons, <kbd>left</kbd> and <kbd>right</kbd> move between them, and <kbd>down</kbd> goes back to the text. Saving empty text removes the placeholder. Undo in the prompt takes back either change.

### Paste dialog

With `prompt.paste_mode` set to `"dialog"`, pasting text opens a dialog before anything goes into the prompt. It works for any text, from <kbd>ctrl+v</kbd> (`input_paste`) or your terminal's paste; the raw paste key (`input_paste_raw`, <kbd>ctrl+x</kbd> <kbd>v</kbd>) still pastes as typed, and images and pasted file paths are attached as before.

```json title="tui.json"
{
  "prompt": {
    "paste_mode": "dialog"
  }
}
```

The options are on the left. The paste as it will go in is on the right, in the prompt's own editor, and it changes as you pick options:

- **insert inline** - puts the text itself in the prompt. Off, it goes in as a placeholder such as `[Pasted ~12 lines]`, however short it is; the title shows which.
- **wrap with \`\`\`** - a code block. Its fence is longer than any run of backticks in the text.
- **wrap with \`** - inline code. Greyed out for text of more than one line. It and the code block exclude each other.
- **quote with >** - a Markdown quote on every line, outside the code block.
- **trim whitespace** - removes trailing whitespace from each line and blank lines at the start and the end. Leading whitespace is indentation and stays.
- **normalize indents** - removes the indentation every non-blank line shares. Tabs and spaces are compared character for character, so a tab is never counted as some number of spaces.
- **remove indents** - removes all leading spaces and tabs from every line, shared or not. While it is on, normalize indents is greyed out: there is no indentation left for it to remove.
- **collapse blank lines** - leaves at most one blank line in a row.
- **join into one line** - makes the paste one line. Blank lines are dropped, and the other lines are joined with a single space, without the trailing whitespace before each break or the indentation after it; spaces inside a line, and at the start and end of the paste, stay. A Windows line ending (`\r\n`) counts as one break. While it is on, collapse blank lines is greyed out, and inline code is no longer greyed out for a multi-line paste.
- **strip ANSI escapes** - removes terminal colors and other escape sequences, as in copied command output.

The cleanups run before the wraps and the quote, so a wrap goes around the cleaned-up text, and join into one line comes after the other cleanups, so a code block or inline code goes around the joined line.

<kbd>up</kbd> and <kbd>down</kbd> select an option, <kbd>space</kbd> or a click toggles it, <kbd>enter</kbd> pastes and <kbd>esc</kbd> cancels. The options you pick are kept for the next paste, also after a restart. <kbd>right</kbd> or <kbd>tab</kbd> moves from the options to the editor, where you can change the text by hand: <kbd>space</kbd> and the arrow keys work as usual there, <kbd>enter</kbd> still pastes, and <kbd>tab</kbd> goes back to the options (<kbd>shift+tab</kbd> also switches either way). Until you type or delete text in the editor, every option undoes itself: turning it off gives back what it changed, and with every option off the editor holds the paste exactly as it came. Moving the caret or the focus is not an edit. After an edit, turning a cleanup off no longer restores what the edit replaced; the wraps can still be turned on and off.

Undo right after a paste takes it back and opens the dialog again with the same text and options, without reading the clipboard again, which may hold something else by then. A click on a placeholder from the dialog opens it with the options it was pasted with.

### Undo in the prompt

`input_undo` and `input_redo`, <kbd>ctrl+z</kbd> and <kbd>ctrl+shift+z</kbd> by default (see [Undo with ctrl+z](/docs/keybinds#undo-with-ctrlz)), step back and forward through what you did in the prompt:

- Typing comes back a word at a time. A pause of more than a second, moving the caret, or switching between typing and deleting also starts a new step.
- A paste, a word or line delete such as <kbd>ctrl+w</kbd> or <kbd>ctrl+u</kbd>, a newline, clearing the prompt and recalling a previous prompt are each one step.
- Undo restores pasted-text placeholders and attachments with their content, not only their labels.
- After you submit, undo brings back what you sent, as if you had pressed up to recall it. The turn it started keeps running, and redo empties the prompt again.

The history is shared by the prompts in one OpenCode window and holds `prompt.undo_depth` steps, 500 by default:

```json title="tui.json"
{
  "prompt": {
    "undo_depth": 1000
  }
}
```

### Prompt history

<kbd>up</kbd> on the first line of the prompt recalls the prompt submitted before, and <kbd>down</kbd> on the last line goes forward again. A shell command run with `!` comes back in shell mode, and a draft of 20 characters or more cleared with <kbd>ctrl+c</kbd> is kept as well.

By default the history is global: every session walks the last 50 prompts submitted in any session on this machine, whichever OpenCode window sent them. With `prompt.history_scope` set to `"session"`, a session walks only the prompts submitted in that session, the last 50 of each. The home screen has no session yet, so there <kbd>up</kbd> still walks every session's prompts, and the prompt that starts a session becomes the first one in its history.

```json title="tui.json"
{
  "prompt": {
    "history_scope": "session"
  }
}
```

Prompts submitted with an OpenCode version older than this setting were not recorded with their session, so no session recalls them; the home screen still does. The history lives in `prompt-history.jsonl` in the OpenCode state directory.

### Older footer settings

These keep working when the matching `footer` key is unset, and `footer` wins when both are set:

- `turn_timing.time: true` is `footer.time: "assistant"`, and `turn_timing.duration: true` adds `assistant` to `footer.duration`. Set, they decide turns on every start and the `/turn-times` and `/turn-durations` toggles last until OpenCode exits.
- `footer_variant: true` is `footer.variant: "all"`.
- `timestamps` takes the type list `footer.time` takes, without `"important"`, and overrides `turn_timing.time`. Its `tool` type also adds tool call durations, as `footer.duration: "tool"` does.

### Startup

OpenCode paints its home screen, with a working prompt, as soon as you run `opencode`, before plugins, agents and providers have loaded. You can type, edit, paste, and click to move the caret right away. The prompt's input keybinds (`input_*`) and the global `tui.json` settings for the prompt's size, the home screen layout, cursor and mouse apply from the start. Project-level `tui.json` files apply once the TUI has loaded.

Opening an existing session with `--session` or `--continue` shows the session screen the same way: the prompt at the bottom, a loading line in the transcript, and the sidebar (when the terminal is wide enough) with the session's last known title, or its ID until it has one. With `--continue` the session is not known until OpenCode loads, so the title appears then.

The agent, model, variant and colors come from the previous run in the same directory, or in the same session. If you press Enter before OpenCode has loaded, the line below the prompt reads "OpenCode still loading, will submit shortly" and the prompt is sent once loading finishes. If the agent, model or variant that loads differs from the one shown, the prompt is not sent and the line reads "Not submitted: agent/model/variant changed". Press Enter again to send it.

Clicking the agent, model, variant, `tab agents` or `ctrl+p commands` below the prompt, or the session title in the sidebar, before OpenCode has loaded shows the clicked text highlighted, and runs its [action](#clickable-elements) once loading finishes. Only the latest click is kept; Escape cancels it.

Dragging across any text on these screens, such as the version, the directory or the sidebar, highlights it and copies it to the clipboard when you release the mouse button, as in the loaded TUI. A drag inside the prompt selects and copies the prompt's text. Any key clears the highlight.

- `instant_prompt` - Show the home screen and prompt while OpenCode starts. Defaults to `true`.
- `early_input` - When `instant_prompt` is off, or with `--mini`, keep the keys you type while OpenCode starts and place them in the prompt when it appears. Enter pressed during startup is dropped. Defaults to `true`.

```json title="tui.json"
{
  "$schema": "https://opencode.ai/tui.json",
  "startup": {
    "instant_prompt": true,
    "early_input": true
  }
}
```

The last agent, model and colors are kept in a small file next to the database (`opencode.tui-startup.json` beside `opencode.db`), so instances with a different `OPENCODE_DB` or data directory keep separate copies.

### Attention

The TUI can request attention for questions, permissions, session errors, and completed sessions. Enable it with `attention.enabled`; built-in events play sounds when triggered, and non-subagent events request desktop notifications only when the terminal is blurred.

- `enabled` - Enable all attention notifications and sounds. Defaults to `false`.
- `notifications` - Allow terminal-mediated desktop notifications when attention is enabled. Defaults to `true`.
- `sound` - Allow attention sounds when attention is enabled. Defaults to `true`.
- `volume` - Default sound volume from `0` to `1`. Defaults to `0.4`.
- `sound_pack` - Sound pack ID to use. Defaults to `opencode.default`.
- `sounds` - Override sound files for `default`, `question`, `permission`, `error`, `done`, or `subagent_done`. Paths can be absolute, `file://` URLs, or relative to `tui.json`.
