## Streamed tool input

- [`73bc224e3b`](https://github.com/Nowaker/opencode/commit/73bc224e3b6e1e9fc9eb366f52b7df85c5f9ad68) (W23): `packages/core/src/session/runner/publish-llm-event.ts` used to collect streamed arguments but publish only the complete `session.tool.input.ended`. It now emits the existing ephemeral `session.tool.input.delta` through the shared 100 ms batching and trailing flush, including before the next block starts. Both events carry the captured assistant message ID. `ended` still carries the authoritative full raw text; atomic and empty-only inputs emit no delta. No wire schema changed, and this did not add partial argument rendering to the main TUI cards.
- The baseline received no delta where one was expected. `w15-w23-gates.result.json` records 33 Core tests, the Solid client store control, 34 workspace typechecks, and the expected failures when the delta callback or cross-block flush was removed. Desktop vt-43 passed all 12 native probes. The contemporaneous m4max build stopped before installation at 11 pass / 1 fail: `tui-reconnect` did not observe the tab strip disappear. That result did not establish the cause of the Mac failure or a successful Mac install.

## CLI config reload logging

- [`fd2b37d7c0`](https://github.com/Nowaker/opencode/commit/fd2b37d7c0dea215f3f2a18d711398bec03be3bd) (W27): the TUI swallowed errors from its serialized `cli.json` reload chain. `packages/tui/src/config/index.tsx` now logs INFO `cli config applied` after applying the new config and ERROR `cli config reload failed` with its cause, tagged by config path. The watch and reload order are unchanged. The log lets the reconnect probe distinguish no observed reload from a reload that explicitly failed.
- `w15-w27-fork.result.json`: both logging tests timed out before the fix and passed after it; 63 TUI config tests and 34 workspace typechecks passed. The companion strict probe (`w15-w27-probe-2.result.json`) passed 12/0/0 on a desktop vt-46 snapshot with `tui-reconnect` reporting `(reload logged)`. That run's unit subset passed 87/0 after excluding an already-failing, unrelated metadata-merge test; it is not a full unit-suite pass. The planned m4max check was not run in these receipts.

## Per-directory plugin source watches

- [`d55b0e119c`](https://github.com/Nowaker/opencode/commit/d55b0e119cdcc43f24a16510706460b2febca5fe) (W26): `packages/core/src/plugin/module.ts` shares one nonrecursive watch per directory for existing local plugin source files rather than opening one native handle per file. Newly discovered files in that directory join the existing subscription and share its readiness. `packages/core/src/filesystem/watcher.ts` can watch immediate entries without a name list; the plugin layer filters updates to tracked names or a filename-less directory event. Missing-file and directory targets retain their original fallback subscriptions.
- `w15-w26.result.json`: the old per-file implementation failed the subscription assertion, the new implementation passed, and removing later-file registration caused the designated 30-second timeout. Related suites passed 99/0 and workspace typecheck passed 34/34. Desktop vt-46 passed all 12 native probes. Ignoring unrelated sibling edits was source-reviewed but not asserted in a test; no Mac-specific result or handle-count benchmark is claimed by this receipt.

## Failed-owner client probe deadlines

- [`beddbc7142`](https://github.com/Nowaker/opencode/commit/beddbc7142b6a209b8f6ef2af1f88e30303c1efa): the Promise and Effect `ensure` tests meant to classify a registered owner's HTTP 500 could hit the 100 ms test probe deadline under load, treat the owner as unanswered and recruit a contender. The fixture then failed with `Missing service command` instead of exercising failed-owner classification. `packages/client/test/fixture/service-timing.ts` makes these two tests wait for the answer within the overall `ensure` budget and outlast that budget with the contender grace. They publish the registration after the fixture is listening. No production timing changed.
- The first shared prefix run hit the flake at 263 pass / 1 fail. After the test-only change, a focused diagnostic at load 54.8 passed both files (45/0); the combined prefix passed the client suite (264/0). This is an observed historical failure and a code-backed race explanation, not a deterministic before/after reproduction.

## Deprecated experimental route aliases

- [`6db5c23fcf`](https://github.com/Nowaker/opencode/commit/6db5c23fcfb32b2136d7781a0be180243bd44f42): `packages/httpapi-codegen/src/index.ts` accepts an alias predicate and `packages/protocol/src/client.ts` excludes `session.recovery` and `session.cancelChild`. Both routes were introduced under `/api/experimental`, not moved there, so there was no old client path to preserve. Regeneration removes the two unnamespaced aliases and their deprecated type names. The actual `client.experimental.session` methods remain, as do aliases for routes that really moved.
- `w15-w24-prefix-2.result.json`: both generation passes were clean. Against the old client/codegen/protocol files, the client suite reported the two expected group/namespace assertion failures (262/2); the combined fixed prefix passed 264/0. The related suite passed 103/0 and workspace typecheck passed 34/34. No separate installed-binary check for generated aliases was recorded.
