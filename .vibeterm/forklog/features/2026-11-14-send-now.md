## Original request

Assigned by coordinator [`ses_ef8235798ffejGr4sa22eXmVNv`](https://portal.vibeterm.desktop.ts.nowaker.net/session/ses_ef8235798ffejGr4sa22eXmVNv), condensing the user's words:

> a user can fire queued non-waking notes now. Examples: OMO's "1/3 tasks completed" continuation note, a vibeterm_notify_session note, anything shown as "note - won't start a turn". Today the only way is revert + resubmit, which rewrites the DB, changes the message id and can cause session-sync divergence.

## Goals

- "Send now" is the first message action on an unread note in the TUI, above Revert, while no turn runs.
- One turn reads every unread queued message, not only the clicked one.
- No note row is rewritten, deleted or re-identified; history only grows by the new turn.
- An HTTP route and SDK method let Portal (through vibeterm-api) do the same.

## Non-goals

- No change to how notes are stored (`noReply`) or to which messages a running turn reads.
- Send now does not unpause a paused session; it refuses (coordinator decision, "choose the refusal for now").
- Notices (every text part `ignored`) are never sent: the model never sees them.

## Rationale and constraints

- A note is a user message stored with `noReply: true`. The loop answers the newest user message after the newest assistant message, so starting the loop over the stored history reads every unread message at once; no new row is needed.
- Revert plus resubmit deleted the note and created a copy with a new id. Two machines holding the same session then disagreed on history, which session sync classifies as divergence.
- As after any turn, the newest message the turn answered later gets its file summary (`summary.diffs`) and a new `time_updated`. That is opencode's normal post-turn write, not a rewrite by Send now; session sync carries it as a row update (opencode-tools `_lib/session-sync/row-updates.ts`).
