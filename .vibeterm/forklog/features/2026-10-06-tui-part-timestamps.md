## Goals

- One `tui.json` key, `timestamps`, naming the transcript entries that show
  a timestamp: `"all"`, `"none"`, a comma-separated list, or an array of
  `user`, `assistant`, `text`, `reasoning`, `tool`, `error`, `compaction`.
- Tool calls show when they finished and how long they ran
  (`✱ Glob "*" (1 match) · 8:05 PM · 500ms`; block tools in their title or a
  trailing line).
- Every format uses `Locale.todayTimeOrDateFirst` from the turn-timing
  feature.
- Unset reproduces vanilla rendering exactly.

## Non-goals

- No live "running since" clock on a running tool (upstream #50891).
- `turn_timing.duration` and `/turn-durations` unchanged.
- No new slash command; `/timestamps` and `/turn-times` keep their names.

## Rationale and constraints

- Vanilla inventory (`907b3bc518` + turn timing): only user prompts
  (`/timestamps`, kv `timestamps`) and assistant footers (`turn_timing.time`,
  `/turn-times`) show a time. Reasoning headers show a duration only; tool
  rows, text blocks, the assistant error box and the compaction divider show
  nothing. Tool and reasoning parts already carry `time.start`/`time.end`;
  text parts carry an optional `time.end`.
- Coexist rather than absorb: unset keeps `/timestamps`, `/turn-times` and
  `turn_timing.time` persisting in kv exactly as before. Set, the list
  decides every type on each start and overrides `turn_timing.time`; the two
  toggles still flip prompt and turn times but only for the running TUI.
- kv-wins was rejected: `kv.json` usually already contains `"timestamps"`
  because the kv store persists its in-memory `kv.signal` defaults with any
  other write, so the config option would be dead on most installs.
- opencode ships no commented `tui.jsonc` template; the JSON schema
  `description` (generated by `packages/opencode/script/schema.ts` into
  `opencode.ai/tui.json`) is the in-editor documentation and lists every
  value.
